# 0.1.1 — 2026-09-19

## Added

- **`browsercompat_get_feature`** — one feature's full record: Baseline state and the date it crossed, standards status, per-browser version added and removed with flags and prefixes, MDN and specification links. Takes a BCD key (`css.selectors.has`) or a web-features id (`has`) and echoes `resolved_as` for which one matched.
- **`browsercompat_check_baseline`** — ship-or-not across up to 20 features per call: Baseline state and dates, the limiting browser, `deprecated` / `experimental` / `discouraged`, and the traffic share requiring each feature would exclude. `all_widely_available` turns on Baseline alone; deprecation does not enter it.
- **`browsercompat_compare_support`** — per-feature verdicts against a required browserslist query, naming each failing target with the reason (`partial`, `prefixed`, `flagged`, `removed`, `unsupported`, `preview_only`) and the traffic share the evaluated targets cover.
- **`browsercompat_search_features`** — the canonical key behind a plain-language name, ranked with `matched_on` naming the field that matched, filterable by BCD namespace and Baseline state.
- **`browsercompat_list_reference`** — the vocabulary the other tools expect, one `topic` at a time: BCD namespaces and browser ids, browserslist agents and their BCD counterparts, Baseline states, web-features groups, ECMAScript snapshots.
- **Four datasets ship inside the package** — `@mdn/browser-compat-data` `^8.1.1`, `web-features` `^3.38.0`, `caniuse-lite` `^1.0.30001810`, `browserslist` `^4.29.0`. No runtime network call, no API key, no rate limit, no server-specific environment variable; every response echoes `data_version`, since a pinned snapshot goes stale on exactly the newest features.
- **Baseline reported per browser-compat-data key, in four states** — `widely`, `newly`, `limited`, and `not_mapped` for a key outside the web-features mapping. Read from `status.by_compat_key` rather than rolled up from the feature, because keys under one feature legitimately disagree.
- **`unchecked_targets`** — every resolved target the server declined to judge, with `no_bcd_browser`, `unknown_version`, or `no_bcd_data`. `all_clear` requires the list empty, so support is never claimed for a browser that was not evaluated.
- **Misses are results, not errors** — an unresolved feature returns `found: false` with `guidance` naming the next call; typed failures carry recovery hints for the input a caller has to fix.
- **caniuse attribution on every response carrying a usage figure** — CC BY 4.0 requires it wherever the data travels, so it rides the `attribution` enrichment field into both `structuredContent` and `content[]`. Full license texts are in `THIRD_PARTY_NOTICES.md`.
