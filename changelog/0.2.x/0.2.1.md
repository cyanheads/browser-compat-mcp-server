# 0.2.1 — 2026-10-15

## Added

- **`feature_support` on multi-key web-features ids** in `browsercompat_get_feature`: one row per Baseline core browser, `{ browser_id, supported, version?, version_is_upper_bound? }`, relaying the release web-features lists for the feature as a whole ([#26](https://github.com/cyanheads/browser-compat-mcp-server/issues/26)).
- **`browsercompat_check_baseline` and `browsercompat_compare_support` judge a multi-key id on `feature_support`**; `browsercompat_compare_support` names the basis in `support_source` (`bcd_key` or `web_features_feature`) and leaves every non-core browser unevaluated ([#26](https://github.com/cyanheads/browser-compat-mcp-server/issues/26)).
- **`compat_keys_total` and `compat_keys_offset` / `compat_keys_next_offset`** on `browsercompat_get_feature`, which pages `compat_keys` 100 at a time ([#25](https://github.com/cyanheads/browser-compat-mcp-server/issues/25)).
- **`other_statements` and the verdict-bearing statement's fields** (`prefix`, `flags`, `partial`, `notes`) on failing `support` and `failing_targets` rows ([#27](https://github.com/cyanheads/browser-compat-mcp-server/issues/27)).
- **`failing_ranges` on each compared result of `browsercompat_compare_support`**: runs `{ agent, newest, oldest, count, verdict }` covering every failing target in the query, identical on every page ([#28](https://github.com/cyanheads/browser-compat-mcp-server/issues/28)).
- **`omitted_features` on `browsercompat_check_baseline` and `browsercompat_compare_support`**: entries past the 20th, returned verbatim for the next call, with `all_widely_available` / `all_clear` false ([#29](https://github.com/cyanheads/browser-compat-mcp-server/issues/29)).
- **`version_is_upper_bound` on `limiting_browser`**, set when the release is a `≤` bound ([#30](https://github.com/cyanheads/browser-compat-mcp-server/issues/30)).

## Changed

- **Three output enums gained members**: the `browsercompat_compare_support` failing verdict adds `before_feature_support` and `no_feature_support`, and its unchecked-target reason adds `no_feature_level_data` ([#26](https://github.com/cyanheads/browser-compat-mcp-server/issues/26)).
- **`compat_keys` on `browsercompat_check_baseline` and `browsercompat_compare_support` results is truncated to the first 10 keys**; `compat_keys_total` gives the full count ([#25](https://github.com/cyanheads/browser-compat-mcp-server/issues/25)).
- **`limiting_browser` keeps a ranged version's upper bound** instead of dropping the `≤` ([#30](https://github.com/cyanheads/browser-compat-mcp-server/issues/30)).
- **Batch inputs are served up to a per-call cap instead of rejected.** `browsercompat_check_baseline` and `browsercompat_compare_support` evaluate 20 of up to 100 features; `limit` on `browsercompat_search_features` (up to 1,000) and `target_limit` on `browsercompat_compare_support` (up to 1,000) clamp to 50 and 10, reported in `cap` ([#29](https://github.com/cyanheads/browser-compat-mcp-server/issues/29)).

## Fixed

- **`browsercompat_search_features` matches singular and plural forms of a query word**, so `container query` finds `Container queries` ([#24](https://github.com/cyanheads/browser-compat-mcp-server/issues/24)).
- **`compat_keys` no longer returns every key of an id on every result**: an id owning 614 keys (`svg`) no longer produces a 775 KB response from 20 entries ([#25](https://github.com/cyanheads/browser-compat-mcp-server/issues/25)).
