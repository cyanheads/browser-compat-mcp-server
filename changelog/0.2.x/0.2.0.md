# 0.2.0 — 2026-09-30

## Added

- **`browsercompat_get_feature` returns `subkeys`** — the direct child keys of the resolved BCD key as `{ total, keys, truncated, next_offset? }`, at most 100 per response, continued with the new `subkeys_offset` input ([#16](https://github.com/cyanheads/browser-compat-mcp-server/issues/16)).
- **`notes` and `impl_url` on `unsupported` and `preview_only` support rows**, merged from the matching BCD statements in declaration order ([#11](https://github.com/cyanheads/browser-compat-mcp-server/issues/11)).
- **`browsercompat_compare_support` reports evaluation per feature**: `failing_total`, `evaluated_total`, `evaluated_coverage_percent`, `unchecked_total`, `unchecked_coverage_percent`, and `unchecked_targets` on each compared result, with top-level `comparable_features`, `targets_resolved_total`, `evaluated_targets_total`, and `unchecked_targets_total`. Each `targets_resolved` row carries `evaluated`.

## Changed

- **`browsercompat_compare_support` pages its target rows** with `target_offset` (default 0) and `target_limit` (1–10, default 10). A query with more than 10 targets returns the first page of rows where it returned all of them; verdicts, coverage, and totals describe the whole query on every page ([#6](https://github.com/cyanheads/browser-compat-mcp-server/issues/6)).
- **`totalCount` on `browsercompat_compare_support` counts the targets in the query**, not the features. `shown`, `cap`, and `truncated` are always present, `nextOffset` continues while targets remain, and an offset past the end returns the summaries with an `offsetNotice`. `unchecked_targets` follow query order.
- **A feature clears only when every target in the query was evaluated and supports it.** With no failing target but any target not evaluated, the verdict is `inconclusive` where it read `clears`, so `defaults` no longer returns `clears` ([#7](https://github.com/cyanheads/browser-compat-mcp-server/issues/7)).
- **`target_coverage_percent` counts only targets whose compatibility data was read** for every compared feature. When no feature is comparable it is 0, and the mapped targets move to `unchecked_targets` with the new reason `no_comparable_feature`.
- **`support[].notes` and `description` are plain text** where they carried HTML: BCD markup is removed, entities are decoded once, and each link reads `label (url)` ([#9](https://github.com/cyanheads/browser-compat-mcp-server/issues/9)).
- **The Markdown text of all five tools escapes literal text**, so a name such as `<dialog>` renders visibly and URLs render as `<https://…>` autolinks. An underscore between two letters or digits is left unescaped, so `and_chr` and tool names stay copyable.
- **The caniuse attribution reads `~97.3%`** (was `~96.7%`) in `attribution`, `usage_source`, and `THIRD_PARTY_NOTICES.md`. The figure is a constant the tests check against the bundled data.
- **Docker image**: production dependencies install in a build-platform `deps` stage, with `scripts/install-otel.ts` adding the OpenTelemetry peers, so no target-platform stage runs JavaScript during a multi-arch build. `lint:packaging` enforces it.

## Fixed

- **`browsercompat_get_feature` returns a top-level `discouraged`** for a discouraged feature whether or not the result carries a BCD `status`, including ids that span several keys. `status.discouraged` stays where it was populated ([#8](https://github.com/cyanheads/browser-compat-mcp-server/issues/8)).
- **`browsercompat_check_baseline` reports `usage_percent_excluded` and `usage_source` for a BCD key only when it is the feature's sole declared compat key.** Other keys omit both instead of borrowing the parent feature's figure ([#13](https://github.com/cyanheads/browser-compat-mcp-server/issues/13)).
- **`limiting_browser` requires full support in every Baseline core browser.** It is omitted when any core browser's support is partial, prefixed, flagged, or preview-only, in both `browsercompat_get_feature` and `browsercompat_check_baseline` ([#14](https://github.com/cyanheads/browser-compat-mcp-server/issues/14)).
