# 0.3.1 — 2026-11-11

## Added

- **`usage_percent_prefixed`** on `browsercompat_check_baseline` results reports the part of `usage_percent_excluded` where the feature works only with a vendor prefix ([#39](https://github.com/cyanheads/browser-compat-mcp-server/issues/39)).

## Changed

- **`limit` (`browsercompat_search_features`) and `target_limit` (`browsercompat_compare_support`)** are honored up to the schema maximum of 1000 instead of being served as 50 and 10; defaults stay 10, and `cap` reports the requested size ([#40](https://github.com/cyanheads/browser-compat-mcp-server/issues/40)).
- **Bundled datasets** refreshed: `browsercompat_list_reference` lists 105 `groups` (was 104), and the caniuse attribution string reports ~97.6% tracked traffic (was ~97.5%).
- **Development tooling** resynced from the framework: skills, `devcheck`, packaging lint, release script, `.env.example` JWT audience and issuer entries.

## Fixed

- **Grouped browserslist tokens** such as `ios_saf 15.0-15.1` are judged at every BCD release they span, so a removal inside the range now fails the target instead of clearing at the lower endpoint ([#38](https://github.com/cyanheads/browser-compat-mcp-server/issues/38)).
- **`usage_percent_excluded`** counts a browser version as supported only for default, unprefixed, enabled support; prefix-required (`x`) and disabled-by-default (`d`) caniuse support are now excluded, except for features whose compat keys are all vendor-prefixed names ([#39](https://github.com/cyanheads/browser-compat-mcp-server/issues/39)).
